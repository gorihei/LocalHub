# ADR-0008: Windowsクリック波紋をクリック透過オーバーレイで表示する

## ステータス

決定・実装済み(2026-09-05)

## 経緯

Local Hubから、クリック位置の波紋をWindows全体へ表示したい。通常のLocal Hubウィンドウ
内だけでは、他アプリ使用中のポインター位置へ描画
できない。低レベルマウスフックはクリックを確実に検出できる一方、入力監視の範囲が広く、
終了処理や障害時の影響も大きい。

## 決定

- Win32の小さなレイヤードウィンドウをクリック位置に作成し、最前面・タスクバー非表示・
  フォーカス不可・クリック透過として表示する。Tauri WebViewは追加しない。
- Windows APIの`GetCursorPos`と`GetAsyncKeyState`を約16ミリ秒間隔で読み取り、入力を
  フックしたり横取りしたりしない。
- 波紋は2つの楕円リージョンの差分としてリング状に描画する。
- Win32 APIは`windows-sys`の必要な機能だけを直接依存関係に追加して使用する。

## 影響

- 効果が有効な間は監視スレッドと軽量なWin32レイヤードウィンドウが動作する。
- 有効状態は既存の`app_settings`へ保存し、アプリ起動時にRustコアが読み込んで復元する。
- 色、形、表示時間、最大サイズ、線幅も`app_settings`へ保存し、監視スレッドがAtomic値から
  読み取ることで再起動なしに描画へ反映する。
- 設定操作は開発者ツールではなく、設定画面の「マウス」タブへ配置する。
- マウス効果はWindows専用とし、非Windows環境では監視処理を行わない。
- モニター構成を実行中に変更した場合は、効果を再作成するため将来的な追加対応が必要になる。

## 見送った代替案

- 低レベルマウスフック: 入力監視範囲とライフサイクル管理が重いため不採用。
- Tauriの全画面透明WebView: 実機でメインウィンドウのドラッグや画面描画へ干渉したため不採用。
- Local Hub本体ウィンドウ内だけの描画: 他アプリ上で波紋を表示できないため不採用。
