# ADR-0006: AI CLIの検出と常駐セッション管理

## 状態

採用（2026-08-22）

## 背景

Codex CLIやClaude CodeなどのAIコーディングCLIを、外部ターミナルを開き直さず
Local Hub内で利用したい。通常のクイックCLIとは別に、作業フォルダーと使用するCLIが
明確な複数セッションを切り替えられる必要がある。

WindowsのGUIプロセスが持つ`PATH`は、VS Codeや起動元ターミナルの環境と一致しない。
実際に、VS Code拡張へ同梱されたCodex、`~/.local/bin`へ入るClaude Code、Volta管理の
CLIが`where.exe`だけでは正しく検出・起動できないケースがあった。

## 決定

### 専用ページとセッション

- サイドバーにAI CLI専用ページを設ける。
- Codex CLI、Claude Code、Gemini CLIを対応対象とする。
- CLIと作業フォルダーを選択すると、既存のConPTY基盤で対話セッションを開始する。
- 複数セッションを同時に保持し、一覧から表示対象を切り替えられる。
- AI CLIページは画面遷移時もマウントを維持し、PTYプロセスを不用意に終了しない。
- 作業フォルダー、ランチャーカードとセッション一覧の折りたたみ状態は設定へ保存する。

### 検出と起動

- `where.exe`が返す候補は、`--version`が成功するものだけを利用可能と判定する。
- Windowsでは`.exe`、`.com`、`.cmd`、`.bat`を拡張子なしshimより優先する。
- PATHにない場合は、次の既知の配置を限定的に探索する。
  - Codex: VS Code / VS Code InsidersのOpenAI拡張同梱バイナリ
  - Claude Code: `%USERPROFILE%\.local\bin\claude.exe`
- 検出と起動は同じバックエンドリゾルバーを使い、表示上の検出結果と実際の起動先を一致させる。
- Volta管理のNodeから`npm run tauri dev`を起動した際に残る`_VOLTA_TOOL_RECURSION`は、
  新しい対話セッションの境界で除去し、古いシステムNodeへのフォールバックを防ぐ。

### セキュリティ境界

- フロントエンドから任意の実行ファイルパスやコマンド文字列を渡せるAPIにはしない。
- バックエンドは`codex`、`claude`、`gemini`の固定許可リストを検証してから、自身で
  解決した実行ファイルだけを起動する。
- CLIの認証情報はLocal Hubへ取り込まず、各CLIが提供する既存の認証・設定をそのまま使う。

## 結果

GUIの`PATH`差異があっても主要なインストール形態を検出でき、作業単位でAI CLIセッションを
常駐させられる。一方、既知の配置以外へ手動インストールされたCLIは`PATH`への追加が必要で、
CLI本体が`--version`を正常終了できない場合は未インストール扱いとなる。
