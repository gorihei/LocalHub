# ADR-0004: プラグイン設定とシークレット管理

- 状態: 採用
- 決定日: 2026-08-22

## 背景

翻訳APIなど外部サービスを利用するプラグインは、APIキーと通常設定を必要とする。
プラグイン固有フォームをホストへハードコードすると、未導入プラグインの設定が表示され、
プラグイン追加のたびにホストを変更する必要がある。またAPIキーをSQLiteやプラグインの
ファイルへ保存すると、バックアップやログを通した漏えいにつながる。

## 決定

プラグインは`manifest.json`の`contributes.settings`で設定の設計図を宣言する。
ホストはインストール済みマニフェストだけを読み、プラグイン詳細画面に汎用フォームを描画する。
ホストは翻訳やDeepLといった固有知識を持たない。

- 通常値はSQLiteの`plugin_settings(plugin_id, setting_id, value)`へJSONとして保存する。
- `secret`値はWindows資格情報マネージャーへ
  `plugin:<plugin_id>:<setting_id>`の名前で保存し、SQLite・ログ・バックアップへ含めない。
- UIへは秘密値そのものを再表示せず、`configured`だけを返す。
- コマンド実行時、ホストは対象プラグインが宣言した秘密値だけを資格情報マネージャーから読み、
  サイドカーRPCの`context.secrets`へ注入する。通常の`params`とは分離する。
- アンインストールは「関連データを残さない」を既定とする。プラグインファイル、通常設定、
  マニフェストで宣言された秘密値、権限許可、ダッシュボード配置、プラグインコマンドを
  参照する自動化フロー、旧形式の名前空間付き設定を削除する。

## 設定型

初期実装は`string`、`secret`、`boolean`、`number`、`select`を扱う。
各設定は`id`、`type`、`title`、任意の`description`、`default`、`options`を持つ。

## 翻訳プラグイン

初期プロバイダーはDeepL API Freeとする。対話型画面は`contributes.pages`で提供し、
プラグイン詳細画面とダッシュボードの両方で同じiframe UIを利用する。
翻訳元自動判定、翻訳先選択、言語入れ替え、Ctrl+Enter、結果コピーを提供する。
翻訳履歴は初期実装では保存しない。

## セキュリティ

- ネットワーク通信前に`network`権限を検査する。
- APIキーをエラー、標準エラー、通知へ出力しない。
- iframeはTauri APIへ直接アクセスせず、既存のコマンドバスを経由する。
- シークレット名は対象プラグインのマニフェスト宣言と照合する。
