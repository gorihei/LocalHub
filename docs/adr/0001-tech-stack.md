# ADR-0001: 技術スタックの選定（Tauri + Rust + React/TypeScript）

- ステータス: 決定
- 日付: 2026-08-13
- 決定者: gorihei

## 背景

REQUIREMENTS.md §12.1は候補としてWinUI 3 / C#を第一候補としつつ、Tauri等のWeb UI資産を使う構成も比較対象になるとしていた（§19 未決事項 #2, #3）。個人開発・単独メンテナンスであることを踏まえ、以下3案を比較した。

| 案 | 長所 | 短所 |
|---|---|---|
| WinUI 3 / C# | Windows統合が最も自然 | トレイ常駐・グローバルショートカット・マルチモニター復元にWinUI 3特有の粗さがある |
| Electron + TypeScript | フロントもバックエンドも同じ言語で書ける（開発者はHTML/CSS/JS経験あり） | Chromium同梱でバイナリサイズ・常駐メモリが大きい。§11.1の「コア常駐メモリ300MB未満」目標と相性が悪い |
| Tauri + Rust + React/TS | WebView2を使い回すため軽量。§11.1の目標と親和性が高い | バックエンド(Rust)は開発者にとって未経験言語 |

Electronは新規に始めるアプリとしてはバイナリサイズの無駄が大きいため不採用。開発者は「必要であればRustを学ぶ」意向を示したため、Tauriを採用する。

## 決定

- **フロントエンド**: React + TypeScript（コアシェルのUIは`design/`のHTMLモックをベースに移植）
- **バックエンド**: Rust（Tauriコマンド / サイドカープロセス）
- **UIフレームワーク**: Tauri 2.x

### 主要コンポーネントの採用ライブラリ

| 要件 | ライブラリ | 備考 |
|---|---|---|
| ターミナル表示 | xterm.js | VS Code / Hyper / Theia採用実績 |
| PTY接続（ConPTY） | portable-pty (Rust, wezterm由来) | MIT/Apache |
| ダッシュボードのドラッグ&リサイズ&衝突回避 | react-grid-layout | FR-DASH-001〜003に対応 |
| コマンドパレット | cmdk | FR-CMD系のUIパターンに対応 |
| 検索ランキング | fuzzysort | FR-CMD-004「決定的な順序」要件に対応しやすい設計 |
| システム情報（CPU/RAM/ストレージ/ネットワーク） | sysinfo (Rust crate) | システムモニタープラグイン向け |
| ポート対応 | netstat2 (Rust crate) | プロセス・ポートプラグイン向け（v1） |
| ローカルDB | rusqlite（bundled SQLite, FTS5可） | §9.1 データ要件 |
| シークレット | windows-rs 経由でCredential Manager / DPAPI | §10.2 シークレット要件 |
| プラグイン間分離 | サイドカー実行ファイル + ローカルIPC（JSON-RPC等） | §12.3 プロセス分離要件 |
| プラグインUI分離 | iframe / Web Component | 1プラグインの描画クラッシュがダッシュボード全体に波及しないようにする |

## 開発ルール

- 開発者はRust未経験のため、Rust側のコードには**処理の意図が追えるレベルの詳細なコメント**を残す。特に以下は必須:
  - ConPTY・IPC・プロセス管理など、Windows API呼び出しの意図
  - unsafeブロックがある場合はその理由
  - Tauriコマンドの入出力契約（何を受け取り何を返すか）
- 難解なRustイディオム（トレイト境界の複雑な組み合わせ、マクロの多用等）は、可読性を優先し避ける。

## 影響

- §11.1のコア常駐メモリ目標（300MB未満）は維持する（Electron案では緩和が必要だったが、Tauri案では不要と判断）。
- §12.1「推奨アーキテクチャ」のスタック候補は本ADRの内容に更新する。
- §19 未決事項 #2（UI技術）・#3（プラグイン実装言語）は本ADRにより決定済みとする。
